# Codex2API 疑似供应链投毒：3.1.10 至 3.1.12 版本紧急避险

2026 年 11 月 23 日，GitHub 上的开源项目 **Codex2API** 被曝出严重的供应链安全事件。根据项目 Issue #916 以及随后发布的独立事件复盘，攻击者疑似利用项目维护者账号的凭据，绕过正常的 `main` 分支发布流程，通过直接推送 Tag 的方式，让 Release 工作流构建并发布了带有后门的二进制程序。

这不是普通的软件 Bug，而是可能导致服务器被远程控制、凭据泄露的安全事件。

## 发生了什么？

事件报告指出，攻击者在没有把恶意提交合并进 `main` 分支的情况下，直接推送了异常 Tag，并触发 Release 构建。

被报告为受影响的版本包括：

- **v3.1.10**：加入了带 Token 门控的远程 Shell 命令执行接口。
- **v3.1.11**：移除了该接口的 Token 校验，形成无需鉴权即可远程执行命令的后门。
- **v3.1.12**：进一步加入环境变量读取、任意 SQL 执行和 TCP 连接等能力。

其中，v3.1.11 的危险程度尤其高。只要攻击者能够访问相应接口，就可能在运行 Codex2API 的服务器上执行命令。

## 不只是程序后门：GitHub Secrets 也可能泄露

独立复盘还披露了更严重的情况：

- 有恶意 GitHub Actions 工作流读取并外传了 Codex2API 仓库中的 16 项 Actions Secrets。
- 被报告涉及的凭据包括部署 SSH 密钥、数据库连接信息、DockerHub、Render、Telegram、GitCode、DeepSeek 等服务的凭据，以及 GitHub Token。
- 报告称，同一套窃密工作流还在该账号下至少 21 个仓库中被推送并成功执行。

这意味着风险可能不止停留在 Codex2API 项目本身。凡是相关仓库中曾经可被工作流读取的密钥，都应按可能泄露处理。

需要注意：以上数量和影响范围来自独立第三方复盘的公开证据分析，不代表每一项凭据都已被证实遭到实际滥用。

## 哪些用户需要警惕？

如果你在 2026 年 11 月 23 日事件发生后做过以下操作，应立即开展排查：

- 下载、安装或运行过 v3.1.10、v3.1.11、v3.1.12 的二进制版本。
- 在 Codex2API 管理后台点击过在线更新。
- 从上述异常 Tag 拉取源码并自行编译运行。
- 在报告所述的异常时间窗口内拉取过相关 GHCR 镜像标签。

**特别提醒：** 独立复盘称，其核查时 GHCR 的相关标签已重新指向 3.1.9 镜像，且 v3.1.11、v3.1.12 镜像未成功发布。因此，不能把二进制 Release 的结论直接等同于所有 Docker 镜像都被感染；仍应结合自己的拉取时间、镜像摘要和部署记录判断。

## 建议立即采取的措施

如果使用过受影响的二进制版本：

1. **立即停止服务**，不要继续运行可疑版本，也不要点击后台在线更新。
2. 回退到报告确认的干净版本 **v3.1.9**。如果怀疑主机已经被执行过命令，优先在干净环境重新部署，不要简单覆盖旧程序。
3. 将应用能够读取的凭据全部视为可能泄露，包括管理员密钥、数据库和 Redis 密码、服务端保存的 API Key、OAuth Token 等，并逐项轮换。
4. 检查访问日志，搜索以 `/i674` 开头的异常请求路径，同时检查服务器是否存在异常外连和未知进程。
5. 如果服务器可以访问数据库、Redis 或内网其他主机，也要检查这些系统是否出现异常访问。

如果你的 GitHub 账号或仓库使用过相关发布链、工作流，建议：

1. 检查 GitHub Actions 工作流是否出现陌生文件、分支、Tag、提交和异常运行记录。
2. 检查相关仓库的 Actions Secrets，把可能暴露的密钥逐项撤销并重新生成。
3. 轮换 GitHub Personal Access Token、SSH Key、Deploy Key，以及其他可能被工作流读取的凭据。
4. 检查同一账号下其他仓库，不能只检查 Codex2API 一个项目。

**不要把旧密钥简单改个名字继续使用。** 应在确认旧凭据已撤销后，重新生成并更新部署环境。

## 最后

这次事件再次提醒我们：软件能从 GitHub 下载，不等于发布物天然可信；主分支看起来干净，也不代表 Tag、Release 和自动更新链路没有被劫持。

对自托管服务来说，最重要的不是急着升级，而是先确认版本来源、校验发布物，并把可能暴露的密钥及时轮换。

**如果你安装或更新过 Codex2API 3.1.10—3.1.12，请先停用并排查，不要抱着侥幸心理继续运行。**
